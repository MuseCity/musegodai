# X 指令分享机器人第一版

日期：2026-09-30。状态：计划已确认，待实施。

## 目标与使用方式

使用官网现有 X 账号 `@musecityxyz`，将用户指定的帖子外链直接发布为该用户的 Musecity Post。用户先绑定并授权，再回 X 发指令；本版只做分享。

使用流程：

1. 用户在 Musecity 登录、绑定 X，并明确授权机器人发布 Post。
2. 在原帖下回复 `@musecityxyz share` 或 `@musecityxyz 分享`。
3. 机器人提取原帖外链，发布到用户的 Musecity 主页和 Square。
4. 回复用户的**指令帖**，提供已发布 Post 的链接。X 当前要求 API 回复由目标帖作者明确召唤；回复指令帖符合这一条件。[X 回复接口](https://docs.x.com/x-api/posts/manage-tweets/introduction)

## 实现方案

- **绑定入口：**新增 `/x-bot`，显示使用说明、连接状态、最近处理结果和断开按钮。未绑定用户收到该页面链接，完成绑定后重新发指令，旧指令不自动执行。
- **身份与权限：**服务端根据已验证 Privy 用户的 `twitter_oauth.subject` 绑定 X 数字用户 ID，不接受客户端指定账号归属或 X 用户名。每个用户配置一个专用 Agent，复用现有邀请、激活与管理流程，权限采用现有必需的 `content:read`、`content:write`，另明确批准 `community:post`。
- **接口：**新增人类账号专用的 `GET /api/v1/me/integrations/x-bot`、`POST` 连接和 `DELETE` 断开接口；写操作要求明确确认。返回连接状态及本人处理记录，不返回凭证。Post 接口和内容类型保持现状。
- **运行：**在现有 Worker 增加每分钟 Cron，以 `since_id` 增量读取官方账号提及；分页结果持久化后推进游标。数据库保存连接、指令处理状态和费用记录，使用租约防止任务重叠。官方账号使用 OAuth 1.0a 用户凭证，源帖以应用级凭证查询，限制为公开可读内容。
- **发布：**明确指令才触发处理；回复指令读取直接父帖，独立指令帖可处理自身链接。提取全部可验证的公开 HTTPS 外链，去重后生成一个 Post，包含链接和原帖来源。超出既有正文上限、无有效链接或原帖不可读时，不发布并返回明确原因。原帖和网页内容均作为数据处理。
- **复用约束：**发布走现有 Agent API，保留认证、暂停、撤销、审核、账号限制及共享每日发布额度。同一指令始终使用固定幂等键和正文快照。Agent 凭证加密保存，密钥及官方账号凭证放入 Worker Secrets。
- **链接体验：**补齐 Post 正文的安全链接渲染，覆盖详情和列表；调整列表的整块链接结构，避免嵌套 `<a>`，保留进入详情的入口。

## 费用与失败处理

- X API 每月上限为 **10 美元**，开发者控制台设置对应限额并关闭自动充值；应用在付费请求前按保守单价预留预算，余额不足即暂停。
- 当前标准帖子读取为 `$0.005`，带 URL 发帖为 `$0.20`，受召唤发帖为 `$0.01`。重叠计费尚未实测，先按每条结果回复 `$0.20` 估算：10 美元约支持几十次完整交互，实际数量还受无效指令和普通提及读取影响。价格为 2026-09-30 的文档快照，启用前重新核对。[X API 价格](https://docs.x.com/x-api/getting-started/pricing)
- 未绑定用户每天最多收到一次绑定引导；普通提及不回复。提供 `@musecityxyz stop` 和站内断开入口，立即停止后续自动处理。每次指令最多自动回复一次。[X 自动化规则](https://help.x.com/en/rules-and-policies/x-automation)
- Musecity 请求失败可用原幂等键有限重试；X 回复结果不确定时记录为待核对，避免重复发送。已发布 Post 保留在站内处理记录中。
- 发布前重查绑定和权限；暂停、撤销或身份不匹配立即停止。超过 24 小时的积压指令不自动补发。
